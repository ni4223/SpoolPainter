# v2.0.2 — Remaining-weight edit + filament-scope lockdown + price-per-spool

**Routing**: post-v2.0.1 patch on the same Open testing track. Sibling
to UI-13 (variant + 5 expander fields, shipped 2026-05-31). UI-13 entry
flips to `partial — variant kept; remaining_weight added; density /
diameter / filament weight / spool weight / price walked back to
read-only on existing-spool` once shipped.

**Status**: planning approved 2026-05-31. Code generation pending.

## What we discovered while planning

While scoping a "remaining weight" field, code-walking
`CreateAndPairUseCase.kt:94-103` + `applyOverridesToFilamentOfSpool`
(SpoolmanRepository.kt:170) revealed two classes of silent edit on the
existing-spool path:

**Filament-scope edits** (PATCH the filament record; cascade to every
spool sharing that filament): `variant`, `density`, `diameter`,
`weight`, `spool_weight`, `price`.

**Tag-only edits** (rewrite NDEF bytes, but the wire model has no
PATCH path back to the filament): `material`, `color_hex`, vendor (via
`vendor_id`), temp ranges. Editing these on an existing spool produces
a tag↔Spoolman desync — tag says PETG Bambu Black, Spoolman still
says PLA Polymaker White.

This patch reframes the form's edit surface by intent:

**Identity + Spoolman-only fields — LOCKED on existing-spool +
existing-filament paths**:
- Material, Brand, Color — locked because (a) editing them rewrites the
  tag without PATCHing Spoolman, producing the desync above, and (b)
  these fields define filament identity — changing them on an existing
  spool means "this is now a different filament", which is a re-pair
  flow, not an edit (deferred to UI-14).
- Density, Filament weight, Spool weight — locked because they're
  filament-scope spec fields and editing them cascades to every spool
  of the filament.

**Stays editable on existing-spool**:
- **Variant** — also writes to the tag as `subtype`; tangible reason to
  fire on Save & Write. PATCHes `extra.variant` on filament.
- **Temp ranges** — most likely "I want to tweak this" field. Rewrites
  the tag on save; Spoolman temp desync accepted as a known limitation
  (no `PatchFilamentBody.settings_extruder_temp` path used today).
- **Remaining + Measured** (NEW) — bidirectional weight inputs with
  stale-prefill guard. PATCHes `spool.remaining_weight`.
- **Price** (REWIRED to spool-scope) — Spoolman supports price on both
  the spool and the filament (spool overrides filament). v2.0.2 moves
  the form's Price field from filament-scope to spool-scope: stored on
  the spool record, PATCHed via `spool.price`. Each spool can have its
  own price. Filament-level price retained as a prefill fallback when
  the spool's price is null.

**Removed entirely**:
- **Diameter** — no UI surface. Defaults to `1.75 mm` (consumer 3D
  printing standard) on new-filament create. Existing filaments
  preserve whatever is stored — we never read it back, never PATCH it.
  Users with 2.85 / 3.0 mm filaments must edit through Spoolman web
  (niche; out of scope for v2 testing-track audience).

## Decisions (locked)

### A. Save UX

Save & Write stays a single button. Same NFC tap re-writes the tag +
Spoolman PATCHes any dirty fields. Idempotent for users who don't edit.
Avoids the UI-14 "two save concepts" rabbit hole.

### B. Field placement + visibility matrix

Material → Brand → Color → Variant → Temp → MoreDetails expander.

### C. Disclosure

One small caption right under the "Weight" section header on
existing-spool path: **"Saved to Spoolman"**. Sets expectation that the
two editable inputs (Remaining + Measured) PATCH Spoolman, not the tag.
No per-field tooltip; no banner. Disabled fields imply "not editable" by
themselves — we don't need to explain why.

### D. Both Remaining + Measured fields, bidirectional

Two `OutlinedTextField`s side-by-side. `measured = remaining +
spool_weight`.

- Edit Remaining → Measured re-renders.
- Edit Measured → Remaining computes (coerced ≥ 0).
- If filament's `spool_weight` is null → Measured field disabled with
  helper `"Set spool weight first"`. (Setting spool weight has to
  happen via Spoolman web today since the field is locked here. We
  accept this gap for v2.0.2 — the niche of "filament with no spool
  weight set + user wants to use Measured" is small. Documented as a
  follow-up.)

### E. Sync rule — Remaining is the source of truth

`form.remainingWeightG: Float?` is the only stored value. Measured is a
computed display + write-side adapter. When `emptySpoolWeightG` changes
elsewhere (today: only on new-filament create; on existing-spool it's
locked), Remaining stays put, Measured re-renders.

### F. Stale-prefill guard

Spoolman is the live source of truth for `remaining_weight` — printer
firmware decrements it during prints. We snapshot the prefill value at
`onSpoolSelected` time. PATCH only fires when the form value differs
from the snapshot.

User direction (audit.md 2026-05-31):
> *"what happens is when in use spoolman keep updating the weight, and
> since we do not refresh often we will have stale weight and let say
> user do not even edit the field weight sent by us will be > than
> spoolman weight so it should not treat this as edit"*

If the user opens an 8-hour-old form, makes no edits to Remaining, and
saves → no spool PATCH. Spoolman keeps its (newer, lower) value.

### G. Empty input semantics

Empty Remaining → "no edit" (null override, no PATCH). Same as the
existing expander field semantics. We do NOT support "explicitly clear
remaining_weight to null in Spoolman" from this UI — niche, deferred.

### H. Visibility of the new row

Existing-spool only. Hidden when `selectedSpoolId == null` (new-spool /
orphan-filament paths). Spoolman defaults `remaining_weight =
filament.weight` server-side on create.

### I. Identity field lockdown — Material / Brand / Color

When `selectedSpoolId != null` OR `selectedFilamentId != null`, the
form's Material picker, Brand picker, and Color picker are **disabled**:
greyed, non-tappable, value visible.

Implementation: each of `MaterialPicker` / `BrandPicker` / `ColorPicker`
gains an `enabled: Boolean` param (or rides the existing one if already
present). Call site at `MainScreen.kt` passes:

```kotlin
val identityLocked = state.form.selectedSpoolId != null ||
                     state.form.selectedFilamentId != null
```

Save & Write still rewrites the tag using the locked-in stored values
on existing-spool path — required because the use case re-encodes the
OpenSpool payload from the form on every save. Locking the inputs
ensures the form's values match Spoolman's stored values, eliminating
the tag↔Spoolman desync class entirely.

If the user wants to change material/brand/color of a paired spool,
they must clear the dropdown (X), re-edit, and save as a new spool
(producing a new pairing). This is the "re-pair flow" that UI-14 will
formalise post-v2.0.

### J. Filament-scope spec lockdown — narrow toExpanderOverrides

The existing-spool save path **must not** PATCH filament-scope spec
fields. Two seams enforce this:

1. **Form-side**: a new `selectedSpoolId`-aware overload of
   `toExpanderOverrides()` that drops density / weight / spoolWeight /
   price / diameter when a spool is selected. Variant still flows.

2. **Repository-side defence-in-depth**: `applyOverridesToFilamentOfSpool`
   already routes through `applyOverridesIfNeeded` →
   `PatchFilamentBody`. We narrow the function's contract to "variant
   only" by dropping density/weight/spoolWeight/price/diameter from the
   patch body it builds when called from the existing-spool path.

   Cleanest: introduce a separate
   `applyVariantToFilamentOfSpool(spoolId, variant)` and reroute the
   existing-spool seam to it. Keep `applyOverridesToFilamentOfSpool`
   for new-filament-existing-spool path
   (`createSpoolForExistingFilament`) where the full override set is
   still legitimate.

### K. Variant stays editable on existing-spool

No change from v2.0.1. The existing-spool seam still patches
`extra.variant` when the form value differs from stored. Continues to
ride Save & Write because variant also lives on the tag.

### L. DecimalField entry bug fixes

Today's `DecimalField` + `updateFloatField` chain has two bugs:

1. **Can't type `.`**. `updateFloatField` calls
   `input.toFloatOrNull() ?: return` which rejects intermediate strings
   like `"1."`. The VM drops the keystroke, the composable re-renders
   the prior Float value, and the `.` never lands. User has no way to
   enter a fractional value via the on-screen keyboard.

2. **No length cap, multiple `.` allowed**. The sanitiser permits any
   number of digits and dots: `"1.2.3"` and `"100000000000"` both
   survive the input filter. They fail to parse as Float and get
   silently ignored, but the visual field accepts the typing.

**Fix shape**: `DecimalField` becomes a small two-state composable —
local string state for in-flight typing, parsed Float committed on blur
(and on each valid intermediate parse for live state).

```kotlin
@Composable
private fun DecimalField(
    label: String,
    supportingText: String?,
    suffix: String,
    value: Float?,
    enabled: Boolean,
    testTag: String,
    maxLength: Int,           // NEW — per-field cap
    onChange: (String) -> Unit,
    modifier: Modifier = Modifier,
) {
    // Local string state so the user can type intermediate states like
    // "1." that aren't yet a valid Float. Committed to the VM as soon
    // as the string parses cleanly.
    var text by remember(value) {
        mutableStateOf(value?.let { formatFloat(it) } ?: "")
    }
    OutlinedTextField(
        value = text,
        onValueChange = { input ->
            // Length cap.
            if (input.length > maxLength) return@OutlinedTextField
            // Allow digits + at most ONE '.'
            val firstDotIndex = input.indexOf('.')
            val sanitised = input.filterIndexed { i, c ->
                c.isDigit() || (c == '.' && i == firstDotIndex)
            }
            text = sanitised
            // Commit to VM:
            //   "" -> null (clear)
            //   parses -> commit
            //   "1.", ".5", etc -> hold but don't commit
            when {
                sanitised.isEmpty() -> onChange("")
                sanitised.toFloatOrNull() != null -> onChange(sanitised)
            }
        },
        ...
    )
}
```

The VM-side `updateFloatField` stays as-is (handles the empty-string
clear; non-empty-but-unparseable case never fires now since the
composable holds those drafts locally).

**Per-field caps**:

| Field            | maxLength | Realistic max     |
|------------------|-----------|-------------------|
| Density          | 4         | 9.99 g/cm³        |
| Filament weight  | 5         | 10000 g           |
| Spool weight     | 4         | 1000 g            |
| Remaining        | 5         | 10000 g           |
| Measured         | 5         | 10000 g           |
| Price            | 7         | 9999.99           |

Diameter is removed entirely (decision K below) so no cap needed.

### M. Price rewired to spool-scope

**Spoolman semantics** (verified against upstream
`spoolman/database/spool.py:191`): price exists on BOTH the filament
record AND the spool record. The GET response returns both raw values
(client decides which to show); sort-by-price uses SQL
`COALESCE(spool.price, filament.price)` — spool first, filament
fallback. This is the same "spool overrides filament" convention the
Spoolman web UI uses.

v2.0.2 honors this:

1. Add `price: Float?` to `SpoolmanSpool` + `CreateSpoolRequest` +
   `SpoolPatchBody` + `SpoolmanRequests.PriceSource` semantics.
2. Form's Price field becomes spool-scope: editable wherever a spool
   is being created or edited (new-filament path, filament-picker
   path, AND existing-spool path).
3. `FormMapping.fromSpoolman` prefill: prefer `spool.price`; fall back
   to `spool.filament.price` if the spool's own price is null. So
   existing data still surfaces in the UI.
4. New `SpoolmanRepository.patchSpoolPrice(spoolId, price)` — sibling
   of `patchSpoolRemainingWeight`. Rides through the same
   `SpoolPatchBody` body shape.
5. New-spool create paths (`createSpoolForExistingFilament` +
   `createSpoolForNewFilamentBundle`) carry `price` to the spool body
   when the form has it. Filament-create ALSO carries the same value
   to the filament record (defensive: if the user later creates a new
   spool of this filament via Spoolman web without setting per-spool
   price, the filament's price serves as the visible default via
   COALESCE).
6. Stale-prefill guard mirrors Remaining: snapshot
   `prefilledPriceMajor: Float?` at `onSpoolSelected`; PATCH only when
   form value differs from snapshot.

`form.priceMajor` field stays in FormState (unchanged name), but its
write target shifts. `toExpanderOverrides` keeps `price` for the
new-filament path (so a brand-new filament still gets a default price
to fall back to), AND a new `form.priceMajor` is dispatched separately
to the spool layer.

### N. Diameter removed from UI everywhere

- New-filament create: diameter input deleted from the expander.
  `CreateFilamentRequest.diameter` always sent as `1.75f` (current
  default). No UI override.
- Existing-spool path: diameter field never rendered (already not
  PATCHed under decision I).
- Existing diameter values on Spoolman records preserved as-is.

            is SpoolmanOutcome.Success -> Unit
            else -> android.util.Log.w(

                "patchSpoolFields failed (non-fatal): $patch",

### 9. `SpoolmanRepository.applyVariantToFilamentOfSpool` (new method)

Narrowed sibling of `applyOverridesToFilamentOfSpool` — handles ONLY
variant. Reuses the existing extra-merge encoding so other extra fields
the user/another tool put on the filament are preserved:

```kotlin
open suspend fun applyVariantToFilamentOfSpool(
    spoolId: Int,
    variant: String,
): SpoolmanOutcome<SpoolmanFilament> {
    val canon = canonVariant(variant) ?: return SpoolmanOutcome.Success(
        // canonVariant returning null = blank-equivalent; nothing to do
        _filaments.value.firstOrNull() ?: return SpoolmanOutcome.ParseError(
            IllegalStateException("blank variant ignored"),
        ),
    )
    val api = cachedApi ?: return urlNotConfigured()
    val cachedSpool = _spools.value.find { it.id == spoolId }
    val filamentId = cachedSpool?.filament?.id
        ?: return performHttp("getSpool") { api.getSpool(spoolId) }
            .flatMap { spool ->
                val fid = spool.filament?.id
                    ?: return@flatMap SpoolmanOutcome.ParseError(
                        IllegalStateException("no filament on spool $spoolId"),
                    )
                performHttp("getFilament") { api.getFilament(fid) }
                    .flatMap { filament -> patchVariantIfChanged(filament, canon) }
            }
    return performHttp("getFilament") { api.getFilament(filamentId) }
        .flatMap { filament -> patchVariantIfChanged(filament, canon) }
}

private suspend fun patchVariantIfChanged(
    filament: SpoolmanFilament,
    canonVariant: String,
): SpoolmanOutcome<SpoolmanFilament> {
    val storedVariant = filament.extra?.get("variant")?.let(::decodeJsonString)
    if (storedVariant == canonVariant) return SpoolmanOutcome.Success(filament)
    val mergedExtra = (filament.extra ?: emptyMap()) +
        ("variant" to GSON.toJson(canonVariant))
    return patchFilament(filament.id, PatchFilamentBody(extra = mergedExtra))
}
```

`applyOverridesToFilamentOfSpool` stays in place but its only remaining
call site is `createSpoolForExistingFilament` (new-spool / existing
filament path).

### 10. `SpoolmanRepository.patchSpoolFields` (new method)

Single seam handles any spool-level PATCH the use case wants to fire.
Carries `remaining_weight` and `price` together when both are dirty.

```kotlin
open suspend fun patchSpoolFields(
    spoolId: Int,
    body: SpoolPatchBody,
): SpoolmanOutcome<SpoolmanSpool> = performHttp("patchSpool") {
    api.patchSpool(spoolId, body)
}.also { o ->
    if (o is SpoolmanOutcome.Success) replaceSpoolInCache(o.data)
}
```

`extra: null` in the body is safe — Spoolman PATCH treats omitted
fields as "don't change" and Gson omits null fields. Failure modes
(404 spool deleted since prefill, 422 invalid value, network) logged
as warnings, don't abort.
