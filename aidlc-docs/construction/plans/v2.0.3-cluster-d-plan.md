## F-2 — Alphabetize pickers, pin "Other" at top

### Decision

- **Sort**: case-insensitive alphabetical (`String.CASE_INSENSITIVE_ORDER`).
- **"Other" placement**: pinned **at the top** — actionable affordance is
  more discoverable than buried at the bottom of an alphabetized list.
- **Scope**: applied to the merged list (presets ∪ Spoolman-derived
  materials/brands). Single source of truth.
- **Where the sort lives**: `MaterialBrandRepository.Companion.mergeMaterials`
  + `mergeBrands`. Picker components don't need to know about ordering —
  they consume `materials.value` / `brands.value` as ordered.

### Implementation

`app/src/main/java/com/spoolpainter/app/data/local/MaterialBrandRepository.kt`:

```kotlin
internal fun mergeMaterials(
    presets: List<Material>,
    spoolmanMaterialNames: List<String>,
): List<Material> {
    val seenUpper = presets.mapTo(mutableSetOf()) { it.name.uppercase() }
    val derived = spoolmanMaterialNames
        .filter { it.isNotBlank() }
        .filter { seenUpper.add(it.uppercase()) }
        .map { name -> Material(name, 200, 220, 50, 70, density = null) }
    val all = presets + derived
    val (other, rest) = all.partition { it.name == "Other" }
    return other + rest.sortedWith(compareBy(String.CASE_INSENSITIVE_ORDER) { it.name })
}

internal fun mergeBrands(
    presets: List<String>,
    vendors: List<String>,
): List<String> {
    val all = (presets + vendors).distinctBy { it.lowercase() }
    val (other, rest) = all.partition { it == "Other" }
    return other + rest.sortedWith(String.CASE_INSENSITIVE_ORDER)
}
```

## F-6 — Refresh staleness

### Decision

Three refresh trigger paths layered, no visible button:

1. **App foreground** — `MainActivity.onResume` → `spoolman.refresh()`.
   Catches the most common case (user edits in Spoolman web in a
   browser, switches back to the app).
2. **Pull-to-refresh on MainScreen content** — Material 3 `PullToRefreshBox`
   wrapping the form scroll. Standard pattern; discoverable through
   gesture rather than a button.
3. **First armed Read after foreground** — when the user enters Read
   mode, if `lastRefreshEpochMs == null || nowMs - lastRefreshEpochMs >
   30_000`, fire a refresh in parallel with the NFC arm. Doesn't gate
   the Read on refresh success — refresh is fire-and-forget.

Throttle: `MIN_REFRESH_INTERVAL_MS = 5_000`. The three triggers are
independent but share a `lastRefreshEpochMs: Long?` clock to avoid
spammy double-refresh (e.g., user backgrounds → foregrounds → taps
Read within 5s → only one refresh fires).

### Implementation

#### Path 1 — onResume

`app/src/main/java/com/spoolpainter/app/ui/activity/MainActivity.kt`:

```kotlin
override fun onResume() {
    super.onResume()
    nfcRepository.attach(this)
    spoolmanRepository.refreshIfStale()  // new throttled entry
}
```

`MainActivity` already has `nfcRepository` injected; add
`spoolmanRepository: SpoolmanRepository` to the same `@AndroidEntryPoint`
constructor injection (Hilt). Fire-and-forget, no UI binding.

#### Path 2 — Pull-to-refresh on MainScreen

`app/src/main/java/com/spoolpainter/app/ui/screens/main/MainScreen.kt`:

Wrap the existing scroll content in `PullToRefreshBox`:

```kotlin
val isRefreshing by viewModel.isSpoolmanRefreshing.collectAsStateWithLifecycle()
PullToRefreshBox(
    isRefreshing = isRefreshing,
    onRefresh = viewModel::onPullToRefresh,
    modifier = Modifier.fillMaxSize(),
) {
    // existing scroll content
}
```

`MainViewModel`:

- new `isSpoolmanRefreshing: StateFlow<Boolean>` — flips true while a
  refresh runs, false on completion (success or failure).
- new `onPullToRefresh()` — `viewModelScope.launch { spoolman.refreshIfStale(force = true) }`.
  `force = true` bypasses the throttle (user-initiated → always refresh).

PTR is gated on `state.spoolman.urlConfigured` — without a URL, the
gesture is a no-op (no work to do). Suppress the spinner in that state.

#### Path 3 — first armed Read

`app/src/main/java/com/spoolpainter/app/ui/screens/main/MainViewModel.kt::onReadTapped` (or wherever the read intent is armed):

```kotlin
fun onReadTapped() {
    viewModelScope.launch { spoolman.refreshIfStale() }  // fire-and-forget
    // existing arm-read logic
}
```

#### `SpoolmanRepository.refreshIfStale`

`app/src/main/java/com/spoolpainter/app/data/remote/spoolman/SpoolmanRepository.kt`:

```kotlin
private val refreshMutex = Mutex()
private var lastRefreshEpochMs: Long? = null
private val MIN_REFRESH_INTERVAL_MS = 5_000L

suspend fun refreshIfStale(force: Boolean = false): SpoolmanOutcome<Unit> {
    return refreshMutex.withLock {
        val now = Clock.System.now().toEpochMilliseconds()
        val last = lastRefreshEpochMs
        if (!force && last != null && now - last < MIN_REFRESH_INTERVAL_MS) {
            return@withLock SpoolmanOutcome.Success(Unit)
        }
        val outcome = refresh()
        if (outcome is SpoolmanOutcome.Success) {
            lastRefreshEpochMs = Clock.System.now().toEpochMilliseconds()
        }
        outcome
    }
}
```

`refresh()` itself stays untouched (still public; existing manual
Settings refresh button still calls it directly).
