## What is in it

### U26 — the brand you choose is the brand that gets written (UI-63)

Reported on GitHub #8: "Brand names (mostly) get all capital when written to the NFC
tag. Jayo becomes JAYO. NextShapes stays NextShapes."

Two changes, which had to land together or the app contradicts itself:

1. **Write path.** `resolveBrandName` rewrote the brand to whatever built-in entry
   matched case-insensitively, so a typed "Tecbears" reached the tag as "TECBEARS"
   while the form still displayed "Tecbears". Now a pass-through; whitespace is the
   only thing normalised.
2. **Brand dropdown.** `mergeBrands` listed presets first and deduped on
   `lowercase()`, so a vendor the user created as "Tecbears" was not merely
   deprioritised, it was **unpickable** — the preset "TECBEARS" shadowed it. Server
   vendors now come first verbatim; a preset is offered only when no vendor matches
   it case-insensitively.

**The justification for the old behaviour was false.** Its comment claimed Spoolman
dedupes vendor rows case-insensitively. Checked against Spoolman's schema:
`vendor.name` is `mapped_column(String(64))` with no unique constraint, index or
collation. It dedupes nothing.

Vendor *records* are still never renamed — `resolveOrCreateVendor` keeps its
case-insensitive match-and-reuse, because renaming rewrites a row every other
filament of that brand points at.

### UI-65 — no status overlay when writing without Spoolman

`computeStatusLabel` had no branch for `ActiveFlow.WritingRaw`, the flow reached only
when no Spoolman URL is set, so `NfcStatusOverlay` never appeared: no "Tap a tag to
write" caption and no animation, while the button *did* flip to Cancel. Found by the
maintainer on device during the U26 install gate.

## Say this in the release notes, not in a support thread

**Old filament records keep their old names.** A user whose Spoolman already holds
`TECBEARS PLA Grau` will not see it renamed — the app deliberately does not
bulk-rename. Only newly created records pick up the corrected spelling. The Play
copy above carries this line for exactly that reason.

**Your dropdown may change spelling.** Where a user's own Spoolman vendor differs in
case from a built-in name, the dropdown now shows theirs. On the maintainer's own
server that changed five rows (`3DHoJor`→`3DHojor`, `Elegoo`→`ELEGOO`,
`eSUN`→`eSun`, `JAYO`→`Jayo`, `SUNLU`→`Sunlu`). Three of those are arguably worse
than the built-in styling — that is server-wins working as designed, and the remedy
is renaming the vendor row in Spoolman once, not softening the rule.

## Known / deliberately unchanged

- **UI-64 (NEW, not fixed)** — blank NTAGs that have never been NDEF-formatted are
  classified as vendor tags and refused, with the write never attempted. Root cause
  **proven in code**; regression pinned to v2.1.1 (U14b vendor expansion). This is
  the real cause of the recurring "NFC is hit and miss" reports. **Strongest
  candidate for the next unit.** Note the reporter currently says it works, which is
  expected — tags rescued with NFC Tools stay formatted.
- **UI-53** — still open and distinct from UI-64. A new mechanism was observed on
  device this session (`BAL_BLOCK` on the foreground-dispatch PendingIntent, which
  got through only because the activity had a visible window). Not confirmed, but it
  fits the symptom better than the parked theory and comes with a candidate fix.
- **`resolveMaterialName` still canonicalises** against the material presets
  (U26 §7 R2). Deliberate: the locked design is brand-only, and PLA/PETG are format
  names rather than vendor styling.
- **Sticky lowercase typo**: typing a lowercase variant of a preset under "Other"
  creates a real vendor row that then suppresses that preset in the dropdown
  permanently. Accepted consequence of "typed input wins"; recoverable by renaming
  the vendor in Spoolman. A confirm-on-near-miss prompt was offered and not taken.
- **2.4.1 shows no "What's new" sheet** — the highlight copy did not change, and
  after U25 the sheet only opens when it has something new to say.
