## F-1 — Weight fields on already-created spools "do not work at all"

**Captured**: 2026-06-05
**Verbatim**: "Weight feilds on already created feilds do not work at all"
**Source**: not yet specified
**Notes**: pending discussion — which weight field(s), what failure mode,
where in the flow. Likely touches v2.0.2's spool-scope edit work
(`prefilled*` snapshot guards, `patchSpoolFields`, DecimalField rewrite).

**Triage 2026-06-06** — root cause confirmed via code-walk. Same bug as
F-13. Two distinct issues live in the existing-spool weight UI:

  1. **Real silent-write bug — Measured field swallows keystrokes when
     both `emptySpoolWeightG` and `remainingWeightG` are null.**
     `MainViewModel.onMeasuredWeightChanged` (line 554-572) takes a
     back-solve branch when `emptySpoolWeightG == null`, which falls
     through to `val remaining = form.remainingWeightG ?: return` —
     silent return. Each keystroke updates the local `DecimalField`
     text via `var text by remember(value)` so the user *sees* "950"
     appear, but the VM never commits a value. Save & Write fires
     with `remDirty=false / emptyDirty=false` → no `patchSpoolFields`
     PATCH → Spoolman never updated. Matches Proto's "i haven't been
     able to set the weight at all" verbatim. The v2.0.2 plan §D
     originally specified disabling Measured with helper "Set spool
     weight first" when `spool_weight` is null, but the back-solve
     mode replaced that and the helper text never landed
     (`MoreDetailsExpander.kt:180-191` — `supportingText = null`).

  2. **UX gap — filament-weight + density read as "locked with no
     exit path".** `filamentSpecLocked = selectedSpoolId != null ||
     selectedFilamentId != null` makes Filament weight + Density +
     Price all greyed on existing-spool path (decision J + decision M
     revised 2026-05-31). No supportingText explains where to edit
     instead. The "Editing these updates Spoolman" caption sits above
     Remaining/Measured but doesn't extend to Empty spool (also
     spool-scope, also editable). Save button still reads "Save & Write"
     even when only Spoolman fields are dirty.

**Routing — locked 2026-06-06**: both issues deferred to **U13** (Action
split: Save vs Write). No v2.0.3 weight hotfix. Rationale: the radio-
style weighting picker Proto suggested (Spoolman parity: gross / measured
/ remaining + auto-fill the other two) is a bigger rework that lands
naturally with U13's form-area reshape; shipping a tactical disable
+ helper-text patch first would just be churn before U13 redoes the
whole section. Testers stay on broken-Measured for now.

# Cluster B Architecture Decision — locked 2026-06-05

**Status**: locked, pending construction unit. Nothing built yet.

The Save & Write button is split into two top-level actions, with Save tied
to the Spoolman record (no tag involved) and Write being the only
tag-touching action.

## Layout

```
Logo + Settings
Banner / hints
┌─ Outer Card ─────────────────────────┐
│  ┌─ Spoolman dropdown ─┐             │
│  │  Spool ▾  [X]       │             │
│  └─────────────────────┘             │
│  ┌─ Filament form ─────┐             │
│  │  Material/Variant/  │             │
│  │  Color/Brand        │             │
│  └─────────────────────┘             │
│  ┌─ More details ▾ ────┐             │
│  │  Temp/Weight/Price/ │             │
│  │  empty-spool/...    │             │
│  └─────────────────────┘             │
│                                      │
│   [ Save to Spoolman ]               │
└──────────────────────────────────────┘
       (scrolls)
   ┌─────────────┬─────────────┐
   │ Read/Cancel │  Write      │  (stationary, bottom)
   └─────────────┴─────────────┘
```

## Decisions (locked)

1. **Two separate buttons, no combo.** `Save to Spoolman` and `Write` are
   distinct actions. No "Save & Write" combo button.
2. **Save = Spoolman-only, no tag.** Save creates/patches the Spoolman
   record (vendor + filament + spool + overrides). It does NOT need a
   tag. UID append moves to Write.
3. **Write = NFC-only.** Write opens the listen window, accepts the next
   tap, appends UID to the selected/saved spool's `extra.card_uids`, and
   writes the OpenSpool NDEF payload. One transaction, single tap.
4. **Write is disabled until form is saved or a spool is selected.**
   Caption: "Pick a spool or hit Save first." Prevents orphan writes.
5. **Vendor-tag Write: disabled with caption.** "Vendor tag — can't be
   written." Matches existing VendorTagHint chip behaviour.
6. **Save lives at the bottom of an outer Card** that wraps all three
   sections (Spoolman dropdown, Filament form, More details). Reverses
   U9b's three-independent-Cards decision in favour of nested Cards
   (outer elevation 1, inner sections are dividers/spacing only). Signals
   "everything in here saves together."
7. **Save label**: `Save to Spoolman` (explicit; tells the user what
   surface gets touched).
8. **Save enabled when form has changes vs prefilled state.** Same logic
   as today's `canSubmit`, repurposed. New spool: form valid + Material/
   Brand/Variant present. Existing spool: at least one editable field
   differs from `prefilled*` snapshot. Save greyed otherwise.
9. **Save success behaviour**: snackbar "Saved spool #N. Tap Write to
   pair a tag." Form stays as-is; spool dropdown auto-selects the new
   spool; Write becomes enabled.
10. **Pair-another flow**: keep `PairAnotherTagSheet` as today. After
    first Write succeeds, sheet offers Pair another / Done. Pair
    another re-arms Write listening on a fresh tap.
11. **Read → Cancel toggle**: 10s timeout retained as a safety net, but
    Read button text/icon flips to `Cancel` (with a subtle spinner)
    while listening. Tappable to abort. Resolves F-12 part 1.

## Items resolved by this decision

- F-9 (Save & Write overloaded) — directly resolved.
- F-11 (Read FAB in the way) — Read becomes stationary in the bottom
  row; no longer a FAB. User had committed to this in chat.
- F-14 (vendor tag explicit Save) — falls out: vendor tags can hit
  Save (Spoolman side fine), Write disabled with caption.
- F-7 (no signal in Read mode) — partially resolved: Read button
  visibly flips to Cancel + spinner; F-7 also wants the same signal in
  the second-tag-listening state of the pair-another flow.
- F-8 (failed-pair-another tooltip references missing button) —
  partially resolved: PairAnotherTagSheet stays, so the button stays
  accessible after the timeout.
- F-12 (cancelable read) — part 1 resolved (toggle to Cancel); part 2
  (no auto-timeout) pushed back in favour of 10s safety net.
- F-6 (refresh staleness) — resolved by side effect: "create spool in
  Spoolman web → open app → pick from dropdown → tap Write" is now a
  first-class flow, since Save isn't required to write a previously-
  created spool.
